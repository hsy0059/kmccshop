# 校园生活服务平台 — 项目系统说明书

## 1. 系统概述

### 1.1 系统定义
校园生活服务平台采用**微服务 + API网关 + 前后端分离**架构，由8个独立微服务、1个共享类库层、1个基础设施层、1个API网关和3个前端应用组成。

### 1.2 设计原则

| 原则 | 实施方式 |
|------|---------|
| 单一职责 | 每个微服务聚焦单一业务领域（用户/订单/配送等） |
| 高内聚低耦合 | 服务间通过HTTP API通信，不直接访问对方数据库 |
| 统一入口 | 所有外部请求通过Ocelot API网关统一路由 |
| 认证统一 | JWT Token跨服务认证，共享密钥和Token验证参数 |
| 数据一致 | 关键业务使用数据库事务，跨服务异步最终一致性 |
| 资源隔离 | 共享数据库但逻辑上每表属于特定服务 |

### 2.2 Docker 容器化架构

项目支持完整的 Docker 容器化部署，所有微服务均可容器化运行：

```
Docker Network: 03_server_campus (bridge)
├── 基础设施层
│   ├── campus_mysql      (MySQL 8.0, :3306)
│   ├── campus_redis      (Redis 7, :6379)
│   └── campus_rabbitmq   (RabbitMQ 3, :5672/:15672)
├── 网关层
│   └── campus_apigateway (.NET 10, :53517, Ocelot)
└── 微服务层
    ├── campus_user       (.NET 10, :53222)
    ├── campus_merchant   (.NET 10, :53523)
    ├── campus_order      (.NET 10, :53216)
    ├── campus_delivery   (.NET 10, :53221)
    ├── campus_campus     (.NET 10, :53211)
    ├── campus_social     (.NET 10, :53215)
    ├── campus_wallet     (.NET 10, :53224)
    └── campus_coupon     (.NET 10, :53225)
```

**端口自动释放机制（三层防护）：**
- 第1层：`PortHelper.cs` — 容器内启动前自动释放 53517/53514 端口
- 第2层：`docker-start.ps1` — 宿主机端口释放（dotnet 进程自动终止，非 dotnet 提示手动处理）
- 第3层：旧容器自动清理（stop + rm）

**容器间通信：** 通过 Docker DNS 解析服务名（如 `mysql`, `merchant.service`），`ocelot.docker.json` 配置下游 Host 为容器别名。

### 2.3 分层说明

| 层级 | 组件 | 职责 |
|------|------|------|
| **前端应用层** | 3个独立前端项目 | 用户交互界面，通过HTTP调用API网关 |
| **API网关层** | Ocelot | 统一路由、认证、限流、日志 |
| **微服务层** | 8个ASP.NET Core服务 | 各业务领域的核心逻辑 |
| **共享类库层** | Campus.Common + Campus.Infrastructure | 公共实体/DTO/工具类/枚举、基础设施封装 |
| **基础设施层** | MySQL/Redis/RabbitMQ | 数据持久化、缓存、异步消息 |

### 5.2 JWT认证体系

```csharp
// 各服务 Program.cs 中的统一认证配置
builder.Services.AddAuthentication(JwtBearerDefaults.AuthenticationScheme)

        options.TokenValidationParameters = new TokenValidationParameters {
            ValidateIssuer = true,

            ValidateLifetime = true,
            ValidateIssuerSigningKey = true,
            ValidIssuer = "campus-platform",
            ValidAudience = "campus-platform-users",
            IssuerSigningKey = new SymmetricSecurityKey(Encoding.UTF8.GetBytes(jwtKey)),
            ClockSkew = TimeSpan.Zero
        };
    });
```

#### 5.5.3 小程序端降级策略

由于微信小程序环境不支持 WebGL DOM（`<canvas>` 标签的 WebGL 上下文与浏览器实现不同），`SphereMenu.vue` 在小程序端（mp-weixin）会通过 `#ifdef MP-WEIXIN` 条件编译自动降级为网格布局（grid layout），仅 H5 端渲染 3D 球形场景。这样既保留了 H5 端的视觉效果，又保证了小程序端的功能可用性。

## 7. 关键技术决策

| 决策项 | 选择 | 理由 |
|-------|------|------|
| 数据库模式 | 共享数据库 | 中小规模项目，简化运维，降低数据不一致风险 |
| API网关 | Ocelot | .NET原生，配置简单，社区活跃 |
| ORM | EF Core + Pomelo.MySQL | 原生.NET支持，Migration管理方便 |
| 缓存 | Redis | 成熟稳定，支持数据结构丰富 |
| 消息队列 | RabbitMQ | 可靠性强，支持复杂路由规则 |
| 管理端框架 | Vue 3 + Element Plus | 企业级UI组件库，功能完善 |
| 移动端框架 | UniApp Vue 3 | 一套代码多端编译，减少重复开发 |
| 身份认证 | JWT | 无状态，适合微服务横向扩展 |
| 密码存储 | PBKDF2-SHA256 | 业界标准，抗彩虹表攻击 |
| 容器编排 | Docker Compose | 开发者友好，单机部署足够 |
| 3D 可视化 | three.js | 粒子背景 / 数据可视化 / 3D 交互菜单 |
| 单元测试 | Vitest + jsdom | Vite 原生集成，three.js mock |
| E2E 测试 | Playwright | 真实浏览器验证 WebGL 渲染 |
