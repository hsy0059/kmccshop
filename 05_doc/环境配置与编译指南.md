## 3. 基础设施（Docker Compose）

项目使用 Docker Compose 管理三个基础服务：MySQL 8.0、Redis 7-alpine、RabbitMQ 3-management。

### 3.1 docker-compose.yml 配置说明

文件位置：`03_server/docker-compose.yml`

```yaml
services:
  mysql:
    image: mysql:8.0                         # MySQL 8.0
    container_name: campus_mysql
    restart: unless-stopped
    environment:
      MYSQL_ROOT_PASSWORD: root123           # root 密码
      MYSQL_DATABASE: campus_platform        # 自动创建数据库
      TZ: Asia/Shanghai
    ports:
      - "3306:3306"
    volumes:
      - ../04_sql/sql/init_database.sql:/docker-entrypoint-initdb.d/01_init.sql  # 建表脚本
      - ../04_sql/sql/init_admin_user.sql:/docker-entrypoint-initdb.d/02_admin.sql
      - mysql_data:/var/lib/mysql
    command: --default-authentication-plugin=mysql_native_password
             --character-set-server=utf8mb4
             --collation-server=utf8mb4_unicode_ci

  redis:
    image: redis:7-alpine
    container_name: campus_redis
    restart: unless-stopped
    ports:
      - "6379:6379"

  rabbitmq:
    image: rabbitmq:3-management-alpine
    container_name: campus_rabbitmq
    restart: unless-stopped
    ports:
      - "5672:5672"      # AMQP 协议端口
      - "15672:15672"    # Web 管理界面
    environment:
      RABBITMQ_DEFAULT_USER: guest
      RABBITMQ_DEFAULT_PASS: guest
```

#### 3.4.2 端口自动释放机制（三层防护）

| 层级 | 实现 | 作用域 |
|------|------|--------|
| 第1层：容器内 | `ApiGateway/PortHelper.cs` — 启动前检测 53517/53514 端口占用并终止旧进程 | 容器内部 |
| 第2层：宿主机 | `docker-start.ps1` 的 `Release-Port` 函数 — 启动前释放宿主机端口 | 宿主机 |
| 第3层：容器清理 | `docker-start.ps1` — 遍历 `campus_*` 容器名，先 stop 再 rm | Docker 引擎 |

**宿主机端口释放策略：**
- Docker 映射端口（53517, 3306, 6379, 5672, 15672）：强制释放任何占用进程
- 本地开发服务端口（53211-53523）：仅释放 dotnet/校园服务进程，非 .NET 进程提示手动处理

#### 3.4.3 Docker 管理脚本

# 一键启动（自动释放端口 + 清理旧容器 + 健康检查）

# 停止所有服务

# 查看日志

### 4.4 appsettings.json 配置

所有微服务的 `appsettings.json` 结构相同（配置文件位于各服务的项目根目录）：

```json
{
  "ConnectionStrings": {
    "DefaultConnection": "Server=localhost;Database=campus_platform;User Id=root;Password=root123;",
    "Redis": "localhost:6379"
  },
  "Jwt": {
    "SecretKey": "CampusPlatform-JwtSecretKey-Min32Chars!@#",
    "Issuer": "CampusPlatform",
    "Audience": "CampusPlatformUser"
  },
  "Logging": {
    "LogLevel": {
      "Default": "Information",
      "Microsoft.AspNetCore": "Warning"
    }
  },
  "AllowedHosts": "*"
}
```

**配置项说明：**
| 配置键 | 说明 | 修改场景 |
|--------|------|---------|
| `ConnectionStrings.DefaultConnection` | MySQL 连接字符串 | 更换数据库地址或密码时修改 |
| `ConnectionStrings.Redis` | Redis 连接地址 | 更换 Redis 地址时修改 |
| `Jwt.SecretKey` | JWT 签名密钥（≥32字符） | 生产环境务必更换 |
| `Jwt.Issuer` | Token 签发者标识 | 保持所有服务一致 |
| `Jwt.Audience` | Token 受众标识 | 保持所有服务一致 |

> **重要**：所有微服务必须使用**完全相同的** JWT 配置（SecretKey/Issuer/Audience），否则跨服务认证会失败。实际代码中，如果 `appsettings.json` 缺失某个值，会从 `Campus.Common.Constants` 中读取硬编码默认值。

### 4.5 Program.cs 启动模板（以 User.Service 为例）

```csharp
using System.Text;
using Microsoft.AspNetCore.Authentication.JwtBearer;
using Microsoft.EntityFrameworkCore;
using Microsoft.IdentityModel.Tokens;
using User.Service.Data;
using User.Service.Services;
using Campus.Infrastructure;

var builder = WebApplication.CreateBuilder(args);

// 1. 控制器
builder.Services.AddControllers();

// 2. JWT 认证（所有微服务共用）
var jwtKey = builder.Configuration["Jwt:SecretKey"] ?? Campus.Common.Constants.JwtSecretKey;
builder.Services.AddAuthentication(JwtBearerDefaults.AuthenticationScheme)
    .AddJwtBearer(options =>
    {
        options.TokenValidationParameters = new TokenValidationParameters
        {
            ValidateIssuer = true,
            ValidateAudience = true,
            ValidateLifetime = true,
            ValidateIssuerSigningKey = true,
            ValidIssuer = builder.Configuration["Jwt:Issuer"] ?? Campus.Common.Constants.JwtIssuer,
            ValidAudience = builder.Configuration["Jwt:Audience"] ?? Campus.Common.Constants.JwtAudience,
            IssuerSigningKey = new SymmetricSecurityKey(Encoding.UTF8.GetBytes(jwtKey)),
            ClockSkew = TimeSpan.Zero
        };
    });
builder.Services.AddAuthorization();

// 3. EF Core MySQL
var connectionString = builder.Configuration.GetConnectionString("DefaultConnection")
    ?? "Server=localhost;Database=campus_platform;User Id=root;Password=root123;";
builder.Services.AddDbContext<UserDbContext>(options =>
    options.UseMySql(connectionString, ServerVersion.AutoDetect(connectionString)));

// 4. Redis 缓存
var redisConnection = builder.Configuration.GetConnectionString("Redis")
    ?? Campus.Common.Constants.RedisConnectionString;
builder.Services.AddCampusRedis(redisConnection);

// 5. 业务服务注册
builder.Services.AddScoped<IJwtService, JwtService>();

// 6. CORS 跨域
builder.Services.AddCors(options =>
{
    options.AddDefaultPolicy(policy =>
    {
        policy.AllowAnyOrigin().AllowAnyMethod().AllowAnyHeader();
    });
});

var app = builder.Build();

app.UseCors();
app.UseStaticFiles();
app.UseAuthentication();
app.UseAuthorization();
app.MapControllers();

// 7. 端口绑定（通过命令行参数或默认值）
var port = args.Length > 0 ? args[0] : "53222";
app.Urls.Add($"http://0.0.0.0:{port}");

app.Run();
```

#### 5.1.2 vite.config.ts 配置说明

```typescript
import { defineConfig } from 'vite'
import vue from '@vitejs/plugin-vue'
import path from 'path'

export default defineConfig(({ mode }) => {
  const isH5 = mode === 'h5'
  const isAndroid = mode === 'android'

  return {
    plugins: [vue()],
    resolve: {
      alias: {
        '@': path.resolve(import.meta.dirname, 'src')    // 路径别名（ESM 写法）
      }
    },
    base: isAndroid ? './' : '/',             // Android 用相对路径
    build: {
      // 根据构建模式切换输出目录
      outDir: isAndroid ? 'www' : (isH5 ? 'dist-h5' : 'dist'),
      assetsInlineLimit: 4096,
      chunkSizeWarningLimit: 1000,
      rollupOptions: {
        output: {
          manualChunks: {                      // 代码分割
            'element-plus': ['element-plus'],
            'vue-vendor': ['vue', 'vue-router', 'pinia']
          }
        }
      }
    },
    server: {
      port: 3000,                              // 开发服务器端口（商家端为 3001）
      proxy: {
        '/api': {
          target: 'http://localhost:53517',    // 代理到 API 网关
          changeOrigin: true
        }
      }
    }
  }
})
```

**ESM/CJS 兼容性说明：**

| 项目 | package.json type | 配置写法 | 说明 |
|------|------------------|---------|------|
| 02_admin | `"module"`（ESM） | `import.meta.dirname` | ESM 项目中 `__dirname` 未定义，必须使用 `import.meta.dirname`（Node 20.11+ 支持） |
| 02_merchant | `"module"`（ESM） | `import.meta.dirname` | 同上 |
| 01_uniapp | 无（CJS） | `__dirname` 可用，但 vitest 配置用 `.mts` 强制 ESM | 因 `@dcloudio/vite-plugin-uni` 依赖 CJS，package.json 不能改为 `"module"`；Vitest 配置文件使用 `vitest.config.mts` 扩展名单独强制 ESM 模式 |

> **Vite 6 预备**：Vite 6 的 native config loader 会以 ESM 方式加载配置文件。本项目已完成 ESM/CJS 兼容性改造：admin/merchant 的 `vite.config.ts` 与 `vitest.config.ts` 均使用 `import.meta.dirname`；uniapp 的 `vitest.config.mts` 通过扩展名强制 ESM。项目已完全兼容 Vite 6。

## 10. 常见问题与解决方案

### Q1：`dotnet build` 报"未找到 SDK"

```
Could not execute because the application was not found
or a compatible .NET SDK is not installed.
```

**解决**：确认安装了 .NET 10.0 SDK

```powershell
dotnet --list-sdks
# 应能看到 10.0.x 版本
# 如果没有，从 https://dotnet.microsoft.com/download 安装
```

### Q2：数据库连接失败 "Unable to connect to MySQL"

**解决步骤**：
1. 确认 Docker 容器已启动：`docker-compose ps`
2. 确认 MySQL 已完成初始化（首次启动需等待约30秒）：`docker-compose logs mysql`
3. 检查 `appsettings.json` 中密码与 docker-compose.yml 一致
4. 手动测试连接：`mysql -u root -proot123 -h localhost`

### Q3：UniApp 编译报 "'uni' 不是内部或外部命令"

```
'uni' is not recognized as an internal or external command
```

**解决**：
```powershell
# 必须使用 --legacy-peer-deps
npm install --legacy-peer-deps

# 如果仍失败，清理后重装
rm -r -force node_modules, package-lock.json
npm cache clean --force
npm install --legacy-peer-deps
```

### Q4：端口被占用（如 3000、53517 等）

**解决**：
```powershell
# 查找占用进程
netstat -ano | findstr :3000

# 终止进程（替换 PID）
taskkill /PID <PID> /F

# 或者修改端口号：
# 前端：修改 vite.config.ts 中的 server.port
# 后端：修改 Program.cs 中的 app.Urls.Add(...)
#       并同步更新 ocelot.json 中的 DownstreamHostAndPorts
```

### Q4b：Docker 启动时报 "address already in use"

**解决**：`docker-start.ps1` 已内置端口自动释放机制。如仍遇到问题：

```powershell
# 手动检查占用进程
netstat -ano | findstr :53517

# 手动终止后重新启动
.\docker-stop.ps1
.\docker-start.ps1
```

### Q4c：Docker 容器内 ApiGateway 报 HTTPS 证书错误

**原因**：容器内没有 ASP.NET Core 开发证书。

**解决**：已在 `Program.cs` 中通过 `DOTNET_RUNNING_IN_CONTAINER` 环境变量检测自动跳过 HTTPS 配置，容器内仅监听 HTTP :53517。如仍报错，确认 Dockerfile 中基础镜像为 `mcr.microsoft.com/dotnet/aspnet:10.0`。

### Q5：`npm install` 报 peer dependency 冲突

**解决**：
```powershell
# 项目已配置使用 --legacy-peer-deps，继续使用即可
npm install --legacy-peer-deps
```

### Q6：Android APK 打包失败 "Android SDK not found"

**解决**：
1. 安装 Android Studio
2. 配置环境变量：
   ```powershell
   $env:ANDROID_HOME = "C:\Users\<用户名>\AppData\Local\Android\Sdk"
   $env:JAVA_HOME = "C:\Program Files\Android\Android Studio\jbr"
   ```
3. 用 `npx cap doctor` 检查配置状态

### Q7：JWT 认证失败 401 Unauthorized

**原因**：各微服务间的 JWT SecretKey 不一致。

**解决**：确保所有服务的 `appsettings.json` 中 `Jwt.SecretKey` 完全相同。

### Q8：Vitest 报 `__dirname is not defined`

```
ReferenceError: __dirname is not defined
```

**原因**：项目为 ESM 模式（`package.json` 中 `"type": "module"`），ESM 环境下 `__dirname` 未定义。

**解决**：将配置文件中的 `__dirname` 替换为 `import.meta.dirname`（需 Node.js 20.11+）：

```typescript
// 修改前（CJS 写法，ESM 下报错）
'@': path.resolve(__dirname, 'src')

// 修改后（ESM 写法）
'@': path.resolve(import.meta.dirname, 'src')
```

对于 uniapp 项目（package.json 无 `"type": "module"`），将 Vitest 配置文件命名为 `vitest.config.mts`（注意 `.mts` 扩展名），单独强制该文件以 ESM 模式加载，即可使用 `import.meta.dirname`。

### Q9：Playwright 报 `WebGL not available`

```
Error: WebGL is not available in the current browser environment
```

**原因**：Playwright 在无 GPU 加速的 CI 环境或某些 headless 模式下，浏览器可能未启用 WebGL。

**解决**：

1. 确认使用 `channel: 'msedge'` 调用系统 Edge 浏览器（而非下载的 Chromium），Edge 默认启用 WebGL 软件渲染 fallback：

```typescript
// playwright.config.ts
use: {
  channel: 'msedge',
  launchOptions: {
    args: ['--use-gl=swiftshader', '--enable-unsafe-swiftshader']  // 启用软件 WebGL
  }
}
```

2. 在 CI 环境（如 GitHub Actions / Azure Pipelines）中，添加上述 `--use-gl=swiftshader` 参数启用 SwiftShader 软件渲染。

3. 确认系统 Edge 浏览器已安装：Windows 系统通常预装；若缺失可从 [microsoft.com/edge](https://www.microsoft.com/edge) 安装。

### Q10：three.js 组件在小程序端不显示

**原因**：微信小程序（mp-weixin）环境不支持浏览器标准的 WebGL DOM API，three.js 的 `WebGLRenderer` 无法在小程序 `<canvas>` 上工作。

**解决**：`SphereMenu.vue` 已内置降级策略，通过 UniApp 条件编译在小程序端使用网格布局替代 3D 场景：

```vue
<template>
  <!-- #ifdef H5 -->
  <canvas ref="canvasRef" class="sphere-canvas"></canvas>
  <!-- #endif -->

  <!-- #ifdef MP-WEIXIN -->
  <view class="menu-grid">
    <view v-for="item in menuItems" :key="item.id" class="menu-item">
      ...
    </view>
  </view>
  <!-- #endif -->
</template>
```

若 3D 组件在小程序端完全不渲染，检查：
1. 确认使用 `#ifdef MP-WEIXIN` 条件编译提供了降级 UI
2. 确认没有在小程序端引入 `WebGLRenderer`（否则会运行时报错）
3. 重新编译：`npm run build:mp-weixin`，用微信开发者工具导入 `dist/build/mp-weixin/` 验证
